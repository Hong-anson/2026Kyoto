# Google Sheets 紅葉資料橋接（選用）

這是唯讀 JSON 橋接器，不是日本網站的現成爬蟲。你提供的部署已確認可匿名讀取，現已設為專案共用預設網址（見 [public/source-config.js](../../public/source-config.js)），不需每個瀏覽器再貼一次。實際回應為 `version:1`、13 筆 `not_configured`，目前沒有真實楓況；表格本身不會憑空產生觀測。以下步驟用於重新部署或建立另一份來源。

## 一次性部署

1. 建立一份**專用** Google 試算表，勿放預約序號、個人資料或金鑰。
2. 從「擴充功能 → Apps Script」開啟綁定腳本，將 `Code.gs` 全文貼入並儲存。
3. 手動執行 `setupBridge`，在 Google 的畫面授權讀寫這份試算表。它會新增 `Foliage` 工作表及 13 個未配置景點，不會覆寫已有內容；既有欄位不符時會停止。
4. 選「部署 → 新增部署 → 網頁應用程式」。執行身分選你自己、存取權選任何人。部分 Workspace 網域禁止匿名部署，這種情況請改用受控後端，不要公開整份試算表。
5. 複製以 `/exec` 結尾的部署網址。`doGet` 只提供公開楓況欄位，沒有寫入操作，也不接受查詢參數切換工作表或抓取目標。試算表本身不必公開分享。
6. 若要覆寫目前專案預設來源，在 App 設定貼上部署網址，或在 Node.js 後端設定 `FOLIAGE_FEED_URL`。後端未設定此變數時沿用共用預設，明確設為空字串則停用後端橋接。請將 `script.google.com` 和重新導向目的地 `script.googleusercontent.com` 加到執行環境的允許網域。請求應取得 `version:1` 及 13 筆 `results`；尚未填資料時是 `not_configured`，不是青葉。

Apps Script 網頁應用程式不保證跨來源瀏覽器讀取。**建議由 Node.js 後端讀取橋接器，再提供同源 `/data/foliage.json`**。GitHub Pages 若無法直接讀取，需另設後端或排程產生靜態快照，不能靠試算表自動消除所有 CORS 問題。

更新程式後，須在「管理部署」將版本切換到新版本；只按儲存不會更新已部署版本。

## 一次補入來源參考連結

既有試算表不必重貼整份程式，也不必重新部署：

1. 開啟 [fill-source-urls.gs](fill-source-urls.gs)，複製完整 10 行函式，貼到你既有 Apps Script 程式的最下方並儲存。
2. 在編輯器上方選擇 `fillSourceUrls`，按「執行」。執行紀錄會顯示實際補入筆數。

此函式會依景點 ID 補入 13 個參考網址：9 個京都景點的 JR 東海介紹頁（本次已取得 HTTP 200），以及 4 個奈良景點的官方入口。奈良連結尚未驗證為楓況觀測頁；吉城園目前只是奈良縣官網入口，仍須另找對應資訊。這些連結均不等於已取得可驗證的現場楓況。

只填入非 `ok` 景點的空白 `sourceUrl`，不改寫既有網址、公式、楓況、原文或任何時間。重複執行不覆寫已填內容；`ok` 列即使缺少來源也不擅自補寫證據。這是由你在自己的 Google 編輯器執行一次；本工具沒有透過公開唯讀網址寫入試算表。若要整份更新，最新版 [Code.gs](Code.gs) 也包含相同函式，且保留結尾 `END KYOTO BRIDGE` 標記。

也可下載 [source-references.tsv](source-references.tsv) 查看完整清單。網址只是資料入口，不能填入 `FOLIAGE_UPSTREAM_URL` 冒充已支援的 JSON 上游。非 `ok` 列的參考網址不會被當成觀測輸出；App 的參考入口也與真實狀態分開。奈良官方網域目前不在觀測來源信任清單，須先驗證真實頁面與時間欄位，再另行支援，不能只補狀態就視為接通。

## 資料欄位

第一列欄名固定，請勿調換：

| 欄位 | 內容 |
| --- | --- |
| `id` | 既有景點 ID，例如 `tofukuji` |
| `state` | `ok`、`unavailable` 或 `not_configured` |
| `status` | 青葉、轉黃、轉紅、見頃、落葉、未知 |
| `rawStatus` | 來源原文，不能用推測補寫 |
| `observedAt` | **來源明示的觀測時間**，例如 `YYYY-MM-DDTHH:mm:ss+09:00` |
| `sourceUrl` | 對應景點觀測的 HTTPS 網址；目前只接受 `weathernews.jp`、`souda-kyoto.jp` |
| `fetchedAt` | 實際讀取來源的時間；不能把它當作觀測時間 |
| `message` | 非 `ok` 記錄的說明 |
| `retrievalError` | 更新失敗或保留舊觀測的說明，可留空 |
| `recordingMethod` | `manual`／`automatic`／`unspecified`；手動填寫預設為 `manual` |

`ok` 記錄必須完整，所有時間需含時區，不能超過現在五分鐘，觀測不能晚於讀取時間五分鐘。來源只給月份日期而沒有年份或有效觀測時間時，必須先確認來源規則，不能假設就是今年或現在。此模板不自動把日期補成當下。

超過 24 小時的記錄保留原始時間並明示過期，App 也必須維持過期判定。格式錯誤、重複景點或不受信任來源對應的景點會回傳 `unavailable`。重新開啟頁面不會替舊資料更新時間。

表格可由你查證來源後手動填寫；那是**手動維護資料**，`recordingMethod` 請保留 `manual`，不可描述成上游自動同步。JSON 自動同步保留上游的記錄方式；上游未標明時輸出 `unspecified`，不自行宣稱 `automatic`。所有列都是公開輸出資料，不要填入任何私人資訊。

## 選用：定時同步「已驗證 JSON 上游」

目前沒有可直接填入的通用日本網站解析網址。只有在已取得合法使用權，且上游確實輸出與 `public/foliage-feed.js` 相容的 JSON 時，才使用此功能。

1. 在 Apps Script「專案設定 → 指令碼屬性」新增：
   - `FOLIAGE_UPSTREAM_URL`：已驗證的 HTTPS JSON feed 完整網址。
   - `FOLIAGE_UPSTREAM_HOSTS`：逗號分隔的**確切**上游與必要重新導向網域。不要用萬用字元。這是管理者設定，不對公開使用者開放；只列你信任的公開服務，勿列內網或存有私人資料的主機。
2. 手動執行 `syncFromConfiguredFeed`。確認成功後檢查 `Foliage` 資料、來源景點對應及原始時間，再執行 `installRefreshTrigger` 建立每 30 分鐘排程。重複執行只會保留本專案此功能的一個排程。
3. 在 Apps Script 執行紀錄查看成功／失敗與觸發器限制。每 30 分鐘是讀取頻率，不是現場觀測頻率；Google 配額、來源限制與觸發器延遲都可能影響更新。

同步只接受驗證後的完整回應；全無可用觀測、HTTP 錯誤、無效欄位或未允許的重新導向都不會先清空資料表。上游漏掉或暫時無法取得某景點時保留其前次有效觀測及原始時間。部分景點過期時照樣顯示過期，不用抓取時間取代觀測時間。

同步會接管固定的 13 筆資料列。啟用自動同步後不要混用手動編輯；若要停止，先刪除 Apps Script 的 `syncFromConfiguredFeed` 觸發器。此功能不帶私人授權標頭，不支援需要金鑰的上游；請勿把金鑰放在公開表格或 App 前端。

如要新增網站爬蟲，應另外實作並測試來源專用解析器：確認真實回應、景點身分、觀測日期與原始楓況、再利用條款和抓取頻率。`IMPORTXML` 無法可靠處理所有 JavaScript 網站，也不能繞過網站存取限制。不得透過這份模板推導或捏造任何景點目前的楓況。
